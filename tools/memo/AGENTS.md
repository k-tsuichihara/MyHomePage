# メモツール開発ルール

## 1. 適用範囲

本ファイルは `tools/memo/` 配下のメモツール本体、関連ソースコード、設計資料に適用する。

リポジトリルートの `AGENTS.md` を共通ルールとして併用する。

DBテスト専用ツール `tools/memo-db-test/` は本ファイルの直接の適用範囲外とし、ルートAGENTS.mdおよびDBテスト専用の既存手順書に従う。

## 2. 既存構成と開発方針

現在のメモツールは、主に以下で構成される。

- `memo.html`
- `js/memo.js`
- `css/memo.css`
- `README.md`
- `doc/` 配下の設計・仕様資料

既存実装はJavaScriptとlocalStorageを利用している。

Ver1.1.0ではTypeScript化とSupabase連携を予定しているが、設計・DBテストの完了を本体実装の完了と解釈しない。

- 現行の動作を確認してから改修する。
- 承認済みのVer1.1.0仕様を基準に実装する。
- フレームワークの新規導入や大規模な構成変更は、理由と影響を提示して承認を得る。
- TypeScriptのソースとブラウザ配信用JavaScriptの関係を明確にする。
- 生成物を直接編集しない構成を優先する。
- ビルド・公開手順が未確定の場合は、実装前に提案する。

### ソースコードのコメント規約

- コメント・JSDocは原則として日本語で記述し、関数名・変数名・型名などの識別子は英語のままとする。
- 処理を逐語的に説明するより、設計意図・理由・前提条件・制約を記す。重要な関数には、必要に応じて目的・引数・戻り値・エラー時の動作をJSDocで説明する。
- データ移行、全件拒否、日時・UUID・revision検証、所有者照合、非破壊性など、安全性に関わる制約には理由を残す。
- 自明な処理への過剰なコメントを避け、まず分かりやすい命名・関数分割を優先する。ただし、変更範囲がコメント整備だけの場合は、実装の改善案を報告し、リファクタリングは別途承認を得る。
- コメントは実装と一致させ、未実装の保証を記載しない。外部由来・自動生成コードを無理に日本語化する必要はない。

## 3. 正式仕様と資料の優先順位

Ver1.1.0の実装では、次の資料を確認する。

- `doc/v1.1.0/memo_v1_1_implementation_review8.md`
- 関連する確定済みSQL、差分パッチ、型定義
- 現在有効な画面設計資料
- `README.md`

`archive/` 配下は過去版の資料として扱い、最新版の正式仕様と混同しない。

資料間に矛盾がある場合は、更新日時だけで判断せず、正式な決定履歴と内容を確認する。

確定できない場合は人間に質問する。

## 4. 既存データと互換性の保護

- 既存のlocalStorageデータを無断で削除・初期化しない。
- データ構造の変更や移行処理は、既存データへの影響を確認する。
- Supabaseとの同期仕様は正式仕様書を基準にする。
- ログイン前後の保存先、データの扱い、同期・移行・競合時の動作を推測で決めない。
- 認証状態によるデータの表示・更新・削除権限を確認する。
- データ消失や重複登録につながる操作には適切なテストを用意する。
- DB側の権限やRLSに関する変更は、共通ルールの承認手順に従う。

## 5. 画面・URL・共通資産の保護

- `memo.html` は既存の公開導線から参照されている。
- ファイル名や配置を変更する場合は、公開URL、リンク、相対パスへの影響を確認する。
- 共通ヘッダー、メニュー、CSS、JavaScriptとの依存関係を確認する。
- 既存の画面構成やユーザー操作を、承認なく変更しない。
- モバイル環境を含めて表示・操作への影響を確認する。
- 必要な構成変更は、移行方法とテスト方針を提示して承認を得る。

## 6. メモツール固有の重点テスト

共通のテスト設計・実行・報告手順は、ルートAGENTS.mdに従う。

本ツールでは、特に以下を重点的に検証する。

- 既存のlocalStorageデータが失われないこと。
- ログイン前後のデータ保存・同期が正式仕様どおりであること。
- 認証・RLS・ユーザー間のデータ分離が保たれること。
- メモの作成・編集・削除・検索・並び替えなど、既存機能に回帰がないこと。
- モバイル環境で表示や操作に問題がないこと。
- データ移行・同期失敗・競合時の動作が正式仕様に適合すること。

ローカルデータ移行機能を実ブラウザへ接続する際は、模擬テストだけでは保証できない実Web Locks・複数タブ・保存容量制限の挙動を、次の関連作業の計画時に確認する。これらの実ブラウザ検証は現時点で未実施であり、解消工程・検証方法・未解消事項の引き継ぎはルートAGENTS.md第11章に従う。

DBテストでは `tools/memo-db-test/` の既存手順・安全制約を遵守する。

## 7. ドキュメントと変更管理

- Ver1.1.0の正式資料を参照し、実装に伴う固有の仕様変更が承認された場合は関連資料を更新する。
- 旧版資料を無断で削除・上書きしない。
- 資料の移動・統合・アーカイブは事前に確認する。
- 承認された作業に、対象外の資料整理や機能変更を混在させない。変更範囲の拡大が必要な場合は、実施前に承認を得る。

レビュー対応の一括承認は、ルートAGENTS.md第8章に従う。メモ固有の仕様変更、既存localStorageの変更・移行、認証・RLS変更、実DB操作の承認条件と安全制約は引き続き適用する。

Git運用、一般的な完了報告、人間による受け入れはルートAGENTS.mdに従う。
