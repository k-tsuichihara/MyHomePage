# ローカルメモ保存：承認済み契約・テスト方針

根拠：[review8統合仕様§2・3](../doc/v1.1.0/memo_v1_1_implementation_review8.md)、[正式型](../doc/v1.1.0/memo_v1_1_types_review8.ts)、[移行基盤](LOCAL-MIGRATION.md)、ユーザーが承認したローカルrequestIdのA案。正式仕様原本は変更せず、限定先行実装として保存先・ロック・時計を注入する。実localStorage・既存画面・実DBには接続しない。

## 保存と読込の契約

- 読込は書込をしない。両キーなしならempty、旧値のみならmigration-required、新値がpendingならrecovery-required。不正値は全体拒否し、初期化・移行・復旧を代行しない。
- 保存は既存の共通Web Locks名で排他し、取得後に新旧キーを再読込する。Web Locks非対応なら書込しない。
- 明示的な初回作成だけ、両キーなしを確認してメモを含むnot-requiredを1回書く。空データの事前書込なし。
- 保存入力はid/title/body/tagIds/expectedRevision/requestIdの6項目。新規入力は第一弾の規則で整形・検証し、受付時に呼出側から独立した値に固定する。
- expectedRevision=nullは作成専用。存在するIDは大小文字を同一視して拒否し、revision=1、createdAt=updatedAt=注入時計、pinnedAt/deletedAt/lastRequestId=nullとする。
- 更新は存在・通常状態・正の安全整数の期待revision一致を要求する。revision上限では加算前に拒否する。createdAt、既存id表記、pinnedAt、lastRequestId（非nullも）は保持し、title/body/updatedAt/revisionだけを更新する。
- タグIDはUUIDとして検証し、同値重複・存在しないタグは拒否する。既存タグの表記を使用し、対象メモの関連だけを本文と同じJSON書込で置換する。タグ自体や他メモは変更しない。
- 全体の候補を再検証し、migrationメタデータは保持する。書込直前にも新旧の生文字列を確認する。書込後は全JSONの生文字列一致と再検証を要求する。
- 書込未試行での失敗はrejected、setItem試行後の例外・読戻し失敗/不一致はunknown。成功・未実行と断定せず、自動再送・削除・ロールバックをしない。未知結果の確認は明示的な再読込で行い、現在値を過去の要求の成功証明にしない。

## requestIdのA案

- requestIdはローカルの保存試行識別だけに用い、永続的な履歴・要求内容・成功receiptは追加しない。ローカルのlastRequestIdを成功・再送判定に使わない。
- 自身のデータプロパティとして取得できるrequestIdがUUID形式検証に成功した直後、他の入力検証やロック取得より前に使用済み集合へ登録する。同じインスタンスでは大小文字違いも同じIDとする。
- その後の入力不正・競合・ロック非対応・書込失敗でも登録を戻さない。新しい明示保存では新requestIdが必要。UUIDとして不正なrequestIdは登録できず、書込なしで拒否する。
- 同じrequestIdは内容が同じでも異なっても再実行を拒否し、過去の結果を返さない。進行中・unknownの場合も同じ扱い。
- 集合はインスタンスの存続中保持し、自動期限切れ・追い出しは行わない。UUIDのみを保持するが長寿命では件数に応じてメモリを消費する。
- 別インスタンス・別タブ・再読込をまたぐ再利用検出、履歴照合、クラウド同等の冪等性、exactly-onceは保証しない。新規メモIDも再試行のために自動再発行しない。
- 完全なMemoRepositoryではなく、load/saveだけのローカル契約とする。resolve・削除・タグ管理等は未実装。

## テストと完了条件

| 観点 | 期待結果 |
|---|---|
| 初回作成・更新 | 1回のJSON書込、全フィールド・日時・revision・lastRequestId保持、読戻し成功後だけsaved |
| 入力・タグ | Unicode境界、型違い、未知/欠落、UUID、重複タグ・不在タグを拒否 |
| 競合・対象保護 | 古いrevision、同revision同時更新、現存ID作成、ゴミ箱、不在、上限を未書込拒否。他の行・メタデータ不変 |
| requestId | 受付時予約、入力不正でも消費、異内容再利用、進行中再利用、unknown後再利用を拒否。別インスタンスの限界を確認 |
| 障害 | 読取・容量・書込後例外・読戻し異常を注入。unknown後の再読込は現在値だけを返し、自動再送なし |
| 非破壊・秘匿 | 旧キー不変、入力の後続変更に依存しない。エラーへ本文・タグ・原例外を含めない |

既存402件を維持し、型チェック・全Vitest・差分検査を実施する。

実ブラウザ・実Web Locks・複数タブ・容量制限は未検証として引き継ぐ。接続工程で隔離した専用テスト環境と検証方法を承認後に用意し、UI接続・公開前に必要な確認を行う。模擬の容量例外と実ブラウザの上限は区別する。ロック外の書込・ABA・最終確認後の変更・複数キーの原子性は保証しない。使用済みメモIDの永続registryや削除後再利用防止も今回の保証に含めず、削除工程で検討する。TS/SQL一致・クラウド接続のゲートも解除しない。
