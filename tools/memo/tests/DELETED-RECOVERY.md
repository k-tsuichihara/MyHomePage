# 完全削除後の単件回復：契約とテスト方針

LOCAL-BACKUP-DESIGN.md §4.4.1とStep 4承認に従う。合成メモリだけへ接続し、公開資産・実ストレージ・移行APIは変更しない。

## 保存境界

バックアップ診断はStep 3の解析器・行別検証・上限を共用する。正常行と現在の削除履歴による回復可否は別に扱う。初期未選択、50件ページ、単件の読取専用プレビューから明示ボタンで直接保存。編集・追加確認ダイアログ・全タグ統合は行わない。

同じストアのrequestId受付時予約とtransactを使い、ロック内で正常v3、元IDの履歴、紐付け可能タグID集合、新ID衝突を検証する。タグ集合が変化すれば書込せず最新プレビューを取得し再操作を要求する。名前変更・無関係な更新は許容する。既存配列・削除履歴・metadataを保持し、新UUID・現在日時・revision=1・lastRequestId=null・非ピン・通常メモを一つ追加。現在に同IDがあるタグだけ関連を追加する。16 MiB超過は全体拒否。

## 状態と診断

書込前拒否は未保存確定。試行後unknownは新UUIDを保持して直後に一回だけ読取診断。正常v3全体とUUID存在で作成確認し、初回内容一致や永続receiptを保証しない。不在・読取失敗・不正データは結果不明。以降は手動診断／独立した再復元／戻るだけで、自動再書込なし。結果不明からの再復元だけ重複可能性を明示する。

作成確認後の通常詳細への読込・遷移は保存結果から分離する。元プレビューへの戻り関連はメモリ内だけで、通常詳細から別画面へ離れた時に終了する。ファイル差替え・画面終了・再読込後の追跡は保証しない。通常画面のドラフト・書込・確認中は開始不可。処理中は他操作を抑止する。

結果不明から一覧へ戻った場合は、該当する元メモUUIDを注意表示用にメモリ内へ保持する。一覧の該当行と同UUIDの再プレビューだけに重複リスクを表示し、別の元メモには表示しない。UUIDは大小文字同値で照合する。この情報は結果判定・再診断用の追跡保証には使用せず、ファイル差替えで破棄する。戻る・再選択による書込や自動再書込は追加しない。

結果不明から独立した再復元を開始する場合も、元メモUUIDの注意を保持してから再検証する。新しい試行がタグ競合等で未書込拒否されても、以前の試行まで未保存確定とみなさず、更新プレビュー・一覧・再選択で注意を維持する。

## 必須検証

- 純粋処理：履歴大小文字同値、正常行と対象判定、不在タグ警告、同ID名称優先、新規タグなし、全属性初期化、原本不変。
- 保存：タグ集合増減は拒否、名前変更・無関係変更は許可、v2/pending/破損拒否、ID衝突、候補上限、共有requestId、単一書込、旧キー・metadata・履歴不変。
- controller：未選択・プレビュー・戻る0書込、連打・遅延再入、unknown直後診断は一回、読取/整合性失敗・新UUID不在、後続編集を許容した作成確認、再復元は新ID、新要求、遷移失敗と保存成功の分離。
- 隔離E2E：ページ・単件選択・テキスト表示、直接復元、現在タグ・不在タグ通知、通常詳細・戻り導線、同ファイル再選択、結果不明案内、既存Step 3回帰。

型チェック・全Vitest・全メモリE2E・preview/persistence/format/transitionビルド・差分チェックを実施する。実localStorage/Web Locks/複数タブ実測、実機モバイル・Firefox/WebKit・最大データ性能は今回の保証外。
