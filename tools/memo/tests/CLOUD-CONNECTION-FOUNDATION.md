# Supabase実接続検証基盤：通信なしの実装・テスト方針

最新mainから、tests/cloud-liveのテスト専用コードだけを追加する。製品RPCアダプター・SQL・公開資産・既存ローカル処理を変更しない。実設定読取・Auth・実通信は未承認のため実装入口へ接続しない。

## 構成と安全境界

- HTTP境界はNode標準fetchに適合する関数を必須注入する。global fetchへの既定値や設定読取は持たない。既存CLIと同じ固定開発Project Ref/HTTPS origin、8 RPCパス、正式引数キーを制限し、redirect:error、15秒timeout、1呼出しで停止する。結果は常にunverified。single-rpc認定は実装しない。
- 15秒はfetch開始から本文読取まで共通のアプリ側待機期限。注入先がsignalを無視してもdeadlineとのraceで呼出側を固定timeoutにし、AbortControllerで中止を要求する。本文取得時に期限をリセットしない。成功/失敗後はタイマーを解除し、期限後のfetch結果から本文読取を開始せず、遅延rejectも処理する。中止はbest-effortで、裏側の処理終了・DB未実行/未コミットを証明しない。同期処理でイベントループが停止する場合のリアルタイム中断は保証しない。結果不明を解消せず、自動再試行しない。
- 通信なし入口は固定の合成シナリオ・模擬応答だけをimportする。実HTTP境界、CLI設定読取、Auth、プロセス環境変数、任意URL/任意シナリオ指定を接続しない。実行引数があれば停止する。HTTP境界自体の試験も偽fetchだけを使う。
- offlineランナーは任意のCloudTransportを受け取らず、合成応答データから生成した専用ポートだけを内部WeakMapで認定する。実HTTP関数や同形オブジェクトの誤注入は送信前拒否する。模擬遅延は解除用Promiseで表し、通信callbackを注入しない。これは固定テストコードの誤接続防止であり、任意の悪意あるNode.jsコードを隔離するsandboxではない。
- ランナーはread（Auth済み相当の合成A/B識別確認）・write・conflict・deleteを分離する。Auth要求を実装したものではない。固定manifestにactor、対象ID、参照タグ、RPC、全引数、期待結果、変更件数の保守的上限を保持し、各段階の回数/変更上限を通信前に検査する。
- 許可はランナー内部WeakMapで段階・実行インスタンスに対応付け、一回限りで消費する。並行実行・再入・次段階への流用・再実行は禁止。段階は順に進め、失敗した実行を再開しない。
- unknown、所有者不一致、予期しない成功/拒否、比較失敗・上限超過は以後の段階を停止する。期待どおりの拒否だけは継続可能。結果不明後の診断は後続の別承認対象で、自動診断・再送・後片付けを行わない。
- 出力は固定の段階/ケース番号/成否/固定理由/呼出件数/変更上限だけ。秘密・本文・実ID・エラー全文・生結果を収集しない。既定の証跡はメモリとサニタイズstdoutだけ。生成物/将来の非公開証跡は.cloud-live配下へ隔離しGit除外する。除外を公開安全性の保証とはしない。

固定offline manifestはread=2回/変更0、write=4回/変更対象上限3、conflict=1回/上限1、delete=3回/上限3とする。変更予算はメモ/タグの論理対象数であり、関連/台帳を含むSQL行数ではない。一括対象数より小さい申告は開始前拒否する。タグ削除等の波及範囲と実DBの対象集合の事前照合は、実接続前に専用データの状態から確認する必要がある。現在の合成ランナーを任意の実保存先へ転用して影響範囲を保証しない。

テスト用許可の発行は合成実行の操作に限定する。実接続許可を発行する機能・Auth呼出し・設定読取・非公開証跡のファイル保存は未実装であり、後続の実接続承認なしに使える切替はない。実行停止時はメモリ証跡を返すだけで、クリーンアップや自動診断を呼ばない。

## テスト計画

| 対象 | 期待値 |
|---|---|
| HTTP制限 | 本番/任意origin・port・userinfo・query等、未知RPC・未知引数をfetch前拒否。1回だけ送信、15秒signal、redirect禁止 |
| 応答 | 200/204・500/P0002・409/PT409のstatus/bodyを保持するがunverified。通信断/timeout/本文解析不能は秘密を含まない固定例外 |
| 許可 | 無許可/偽造/別実行/別段階/再利用/二重実行を未通信で拒否 |
| 上限 | RPC・対象・参照ID・全引数・呼出回数・変更件数、失敗後停止。拒否でも試行予算は戻さない |
| 結果 | 正常/競合/拒否/所有者不一致/receipt/null/unknown。期待外成功・unknown後の後続書込0件 |
| ベクトル | UUID・Unicode・日時・revisionをTSで照合。SQL側へ渡す正規化済み入力と生不正入力の別レーンを記録する |
| 非接続・秘匿 | global fetch/Auth/設定読取に依存しない入口、合成fixtureのみ。任意の応答/例外がログへ混入しない |

SQLベクトルの実行は今回行わない。TS新規入力の整形とSQL正規化済み値の検証は責務が異なる。孤立サロゲート/NULなどはHTTP/DB型の拒否層も別に記録し、同じSQLSTATEを推測で決めない。日時はDBによる表記変換、revisionはDB生成値なので、RPCの入力として任意属性を追加しない。

## 実行と完了条件

メモ配下で`npm.cmd run test:cloud-offline`。固定offline入口だけをesbuildで.cloud-liveへ生成し、実行結果にもmode=offline、SQL/Auth=not-runを明示する。引数によるlive化や動的モジュール指定は提供しない。共通ベクトルは`vectors.ts`、HTTP境界の偽fetch試験と段階許可試験は`cloud-connection.test.ts`。

型チェック、全Vitest、専用offlineビルド/実行、既存4ビルド・E2E群、差分確認。ネットワークエラーが出ても実接続へフォールバックしない。実HTTP経路・Auth/RLS/GRANT・SQLベクトル一致・single-rpc認定は未検証とする。今後の実接続・認証情報読取・ユーザー準備・段階別書込/削除は個別承認が必要。
