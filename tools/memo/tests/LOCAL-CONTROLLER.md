# ローカルアプリケーション制御層の契約・結合テスト方針

根拠：[review8統合仕様§1・3〜5](../doc/v1.1.0/memo_v1_1_implementation_review8.md)、[保存](LOCAL-SAVE.md)、[追加操作](LOCAL-OPERATIONS.md)、[一覧](MEMO-QUERY.md)、[編集](EDITOR-STATE.md)とPR #11の承認条件。実UIやブラウザ保存先へ接続せず、注入した同一ローカルストアを継続利用する。

## 公開境界

- createLocalMemoController({store, createId})で生成し、getStateとdispatchを提供。storeは既存createLocalMemoStoreのload/save/changeState/saveTag/deleteTagだけ。時計・保存先・ロックはストア側へ注入済みとし、この層では取得しない。テストは合成メモリ保存先と遅延可能なポートだけを使用する。
- コマンドはload/query/detail/edit/new/draft/save/mutate/list/adjacent/confirm。実認証・保存先切替・移行実行・復旧・完全削除は公開しない。作成IDとrequestIdは注入生成器を用い、同じIDの自動再発行・要求の自動再送をしない。
- 状態は入力から独立した不変スナップショット。データ・一覧・編集・読込状態・書込結果を分離する。ドラフト・要求・確認材料はメモリ内だけで保持し、ログや永続化対象にしない。

## 読込・編集・保存

- emptyだけを正常な空データとして扱う。旧キーのみ、pending、破損、取得失敗は停止状態。以前の取得データ・一覧・ドラフトがあれば保持し、利用可能な最新データであると装わない。停止／読込中は新たな書込や編集開始を許可しない。既存ドラフトの編集は継続できる。
- 同時書込は一件。保存中のdraftコマンドは許可する。beginSave→同一store.saveを一度だけ呼ぶ→settleSaveの順で接続する。追加編集が残る場合、制御層のrouteはeditを維持する。既存settleSaveのscreen=detailを無条件に採用しない。
- 成功時だけ一覧更新のためloadする。書込成功と後続load失敗は独立して保持し、後続失敗で成功をunknownへ戻したり、保存を再試行したりしない。queryMemos/countTagUsageを再利用し、一覧件数と使用件数を混同しない。
- loadの応答には世代を付け、書込開始・新しいloadで古いloadを失効させる。古い応答は一覧や編集へ反映しない。ロード成功でもeditorを再生成せず、編集基準のメモ／関連と現在値を比較しchanged/missing/trashed/missing-tag/id-existsを明示する。revisionを自動更新しない。
- queryとscrollTopを保持し、詳細へ入る時の一覧順をdetailListへ固定して前後移動に使う。対象不在・結果外では別メモへ暗黙に移動しない。

## 確認・追加操作

- mutateは既存ピン／ゴミ箱／タグ操作。編集画面では追加操作を抑止し、まず既存の離脱確認で編集を終了させる（インラインのタグ作成等は今回提供しない）。タグ削除とtrash/restoreは必ず明示確認を要求する。
- 確認は最新の一枚だけを保持し、単調増加token、操作種別・対象ID・期待revisionを含む不変コマンド、確認表示時の状態世代へ結び付ける。load開始／結果・編集・検索条件変更・別確認などで世代が変われば、古い確認は実行しない。実行時も現スナップショットの対象とrevisionを再照合する。最後の競合検出はストアの共通ロック内検証に委ねる。
- メモ以外の操作でも成功／拒否／結果不明を区別。例外は元の内容を捨て結果不明とする。unknownの要求・requestIdは未解決集合へ保持し、明示loadが一致しても解決済みにしない。その後の書込は新IDで再確認が必要。再保存時のeditor側確認も明示承認後だけ発行する。
- 離脱ではPR #10のrequestNavigationを利用し、未保存・拒否・不明の確認を維持する。全体の追加操作が拒否／不明であった場合も確認対象。明示確認した離脱でも未保存editorはretainedEditorsへ保管する。自動破棄はしないが、ページ終了後の復元は保証しない。

## テスト観点・完了条件

| 観点 | 期待結果 |
|---|---|
| 一連の利用 | 読込→検索→詳細→編集→保存→一覧復帰、条件・スクロール・前後順を保持 |
| 追加操作 | タグ・ピン・ゴミ箱・復元・使用件数、確認なしの削除なし、対象外不変 |
| ドラフト | 保存中の追加編集を保持しeditを維持、再読込で再生成せず対象不整合を通知 |
| 障害 | 確定成功＋再読込失敗の分離、拒否・不明・例外、自動再試行なし |
| 非同期 | 二重書込拒否、順序逆転ロード無視、書込前ロードの失効 |
| 確認 | token・世代・対象／revisionの照合、キャンセル、編集／load／対象変更後の旧確認拒否 |
| 互換性 | 旧キー・pending・破損を空にしない、移行や自動修復なし、旧キー不変 |
| 既存契約 | 同一ストアのrequestId再利用拒否を維持、既存716件＋追加結合テストと型チェック |

ブラウザ・実localStorage・Web Locks実挙動・複数タブ・容量制限・DOM・Auth・Supabase・SQLは未接続／未検証。接続工程で隔離origin・専用プロファイル・合成データ・生成JS・成果物公開除外・対象ブラウザと検証手順を承認後に準備する。未解決要求や保持editorの長期メモリ増加は残存リスク。正式仕様原本と安全ゲートを変更しない。
