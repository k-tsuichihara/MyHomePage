# v3形式・互換性と隔離導入の契約

PR #17の承認に基づくReview8のローカル保存形式への追加契約。旧v2検証・v1→v2移行・pending復旧の原契約は維持する。

## API境界・形式

- 同じ`myhomepage.memo.data.v2`キーにversion=3、既存5項目と必須`deletedMemoIds: UUID[]`を保存する。migrationは既存のnot-required／complete／pending構造を保持する。
- `local-format.ts`がv2／v3を識別する。v3の欠落・未知項目、UUID同値重複、現存メモとの履歴衝突、壊れた関連・migrationは全体拒否。UUID原表記・日時精度・順序・revisionは保持する。v3 pendingは構造検証できても利用・旧復旧不可。
- 通常データ層はv2を読んでも自動更新しない。全通常操作でversion・migration・履歴の原配列を厳密に保持する。新規作成は大小文字同値の削除済みIDをdeleted-idとして拒否し、自動再採番しない。履歴を要求台帳に使わない。

## 許可の境界

形式更新の書込入口・許可発行器は`tests/format/controlled-upgrade.ts`だけに置き、製品srcへ輸出しない。隔離ランナーの固定fixture投入、同じ環境の既存移行／復旧成功の直後に、fixture担当だけがissuerへ生値を登録する。UIへはissuerを渡さない。

許可は内部WeakMapのオブジェクト同一性で、ランナー環境・保存先オブジェクト・新旧キー生値・診断世代と対応付ける。任意のtrueや同形オブジェクトでは許可されない。再診断・キャンセル・確認消費で失効し、ロック内で世代と生値を再照合する。生値をDOM・URL・ログへ出さない。これは協調する隔離fixtureの導入経路確認で、暗号学的証明や任意の同一originコードへの防御ではない。ABAや保存領域の外部置換の履歴は証明しない。

任意v2は構造が正しくても未登録なら停止する。実ユーザーのv2導入元確認・許可発行は未実装。初期データなしの通常明示保存は既存どおりv2を生成する。起動だけで書かない。

## 更新・復旧・ロールバック

診断は読取だけ。許可と明示承認が揃い、共通ロック内で再照合できた場合のみ、complete／not-requiredのv2からv3へ単一JSON書込・読戻しを行う。削除済みIDは当該管理経路に限り空で開始する。v1移行・v2 pending復旧は元APIで先に完了し、成功結果をfixture担当が登録、別の診断・承認で更新する。v3へ旧移行／復旧を実行しない。

未書込拒否は無変更。書込試行後は例外・不一致をunknownとし、旧値書戻し・再送・初期化をしない。再診断でv3が見えても過去要求を確定成功へ変換せず、現在値の状態として表示する。再試行する場合は新診断・新許可・新承認が必要。

旧v2書込基盤のPR #16時点のfixtureで読込・書込・旧移行／復旧のv3拒否を確認する。保守モードはv3対応読込と停止案内だけで、保存・移行・復旧・逆変換を提供しない。製品公開前にv3対応保守版の整備・受入が必須。今回の保守UIは隔離試験用だけ。

## テスト方針・公開ゲート

`tools/memo`で`npm.cmd run test:format`を実行すると専用ビルドと所有ガード付きランナーを実行する。任意profileや本番originを引数指定できない。生成物は`.format/`、profileは既存の`.browser-profiles/`へ隔離し、双方Git除外する。失敗profileの生パス・内容はPRへ転載しない。

形式全項目・履歴・UUID・参照整合性、原入力の後続変更からの独立性、許可なし／偽造／別環境・領域／世代失効、二重確認、承認後変更、同時更新、ロック非対応、容量・書込・読戻し障害、失敗後再診断、旧キー・snapshot不変を合成データで検証する。

全通常操作の履歴保持と履歴を消す変換の未書込拒否、v1移行／pending復旧後の別承認、旧コード拒否・保守モード不変を単体・結合・管理Chromiumで確認する。既存Vitest・メモリE2E・所有profile永続化E2E・切り替えE2Eとビルドを回帰実行する。実ストレージは生成・所有確認済みprofileと専用loopback originだけ。失敗profile保全／所有検証後の破棄、CSP・外部通信制限はPR #14契約を再利用する。

## 残課題

履歴を間引かず、容量上限では停止する。UUID1件のJSON配列は概ね39文字でありブラウザ容量換算とは異なる。全JSON検証・再生成の時間・メモリ・実容量は規模依存で、今回の試験上限を超える保証をしない。

将来のバックアップは履歴を含める。古いバックアップで現在v3を単純上書きしない。履歴統合・衝突・削除メモ復活防止は別設計。全保存領域喪失・サイトデータ消去までの永久保証はしない。旧キー／legacySnapshotの内容消去とID再利用防止は別契約。

完全削除・一括削除・バックアップ取込・Supabase/Authは未実装。旧JSは旧キーへ書ける問題、製品接続、Pages公開元確認、公開切り替え・保守版配信・他ブラウザ・実機受入は未解決。試験成功を本番公開承認と扱わない。
