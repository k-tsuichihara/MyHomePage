- PASSはHumanの観測に基づく。新たなSKIPは理由・オーナー判断・引継ぎ先を必要とする。環境不足を自動的にSKIPへ変更しない。
- FAIL時はそのケースを停止→下表へ記録→依存する後続ケースを止めるか判断→必要な修正→AI Gate→影響範囲だけHuman再確認する。全UATのやり直しを原則にしない。
- 今後の各UAT問題も、本書内に「Human観測」「修正内容・commit/PR」「AI Gateの実行範囲・結果」「修正後にHumanが行う具体的操作・見る結果」「Human再確認結果」を対応する問題ID付きで残す。PRや会話への参照だけで操作手順・結果を省略しない。未報告の観測やHuman PASSを推測で埋めない。
- 再確認は問題記録と本書の操作手順へ紐付け、実施build・日時・観測・PASS/FAIL/未実施・後続ケースへ再利用する項目を記録する。同じbuild・同じ前提で既にHumanが確認した項目は再利用し、修正の影響がない操作を再実施対象へ戻さない。後続ケース全体を自動PASSにする意味ではない。
- UNKNOWN・予期しない認証／通信エラーは成功・未実行と断定しない。同操作の再送、cleanup、データ初期化や巻戻しをせず停止する。技術的な切り分けはAI側で行い、人間にログ解析を求めない。
- 期待結果を満たすが使いづらい場合もUX指摘として記録する。受入を妨げるならFAIL、改善希望として受け入れる場合はPASS＋備考とし、オーナーが判断する。
