# 第二弾：読み取り検証の承認済み契約・テスト方針

根拠：[統合仕様§2〜5](../doc/v1.1.0/memo_v1_1_implementation_review8.md)、[正式型](../doc/v1.1.0/memo_v1_1_types_review8.ts)、review8 SQLの型・制約・memo_load_snapshot、および第二弾の追加条件に対するユーザー承認。正式資料原本は変更しない。

- 旧配列、local v2、DB snapshotをunknownから全件検証する。未知・欠落・型違い・重複・孤立関連・所有者不一致は全体拒否。空配列は有効、nullは空として扱わない。
- 日時：西暦0001〜9999の実在日、T、00〜23時、00〜59分秒、任意の1〜6桁小数秒、Zまたは±00:00〜±23:59。地域タイムゾーンとの対応は検証しない。閏秒、24:00、拡張年、日付のみ、タイムゾーンなしは拒否。原文字列を保持する。
- UUID：8-4-4-4-12の16進、version/variant制限なし。照合のみ大小文字を同一視。旧IDは非空文字列でUUID不要、大小文字は区別する。
- 保存済み文字列は新規入力の整形結果と同一であることを要求する。本文・Unicode表現を補正しない。全フィールドを検証する。
- local revisionは正の安全整数、DB revisionは同数値または先頭ゼロなし十進文字列。DB結果はsnake_caseとrevisionの原表現を保持する。
- legacySnapshotはJSON解析と旧配列全件検証まで。pending/completeとも保持した元文字列を返す。completeの現データは編集可能なので旧配列との恒久的一致を要求しない。
- 成功値は新規のオブジェクト・配列で構築する。入力の後続変更が影響しない。unknown入口はJSON相当のプレーンなデータだけを対象とし、アクセサ・追加プロパティ・疎配列を拒否する。悪意あるProxyの副作用を隔離する仕組みではない。
- エラーには固定コードのみを含める。タイトル・本文・タグ名・legacySnapshot・未知キーやJSON構文エラーの実値を含めない。

| テスト群 | 正常・境界 | 拒否・保護 |
|---|---|---|
| 日時 | 閏年、年境界、オフセット上限、小数秒1/6桁 | 不正暦日、閏秒、24時、拡張年、小数7桁、形式・型 |
| UUID/revision | 任意version、大小文字、nil、安全整数上限 | 不正形式、同値重複、0/負/非整数/unsafe、DB非十進表記 |
| 旧形式 | 非UUID ID、本文空白・LF/TAB、順序保持 | 未知/欠落/型、空タイトル、前後空白、文字数・禁止文字、全体拒否 |
| v2 | 3状態、空集合、legacySnapshot解析 | メタデータ異常、参照不整合、ID/タグキー/関連重複 |
| DB | 所有者照合、snake_case保持、revision原表現 | null、所有者不一致、未知列、欠落・孤立関連 |
| 非破壊・秘匿 | 凍結fixture、入力後続変更、JSON入口 | 失敗時も入力不変、エラー実値なし |

第一弾165件の期待値・実装は維持し、型チェックと全Vitestを実行する。合成fixtureのみで、実localStorage・認証・ネットワーク・DBには接続しない。

## 第三弾以降との境界

validateLocalV2のvalidated-pendingは構造検証成功であり通常利用不可。validated-complete/not-requiredは形式・整合性検証成功であり、書込権限や実キー状態の保証ではない。第三弾でWeb Locks下の実キー再読込、旧生文字列一致、移行内容・順序・初期値照合、書込と読戻しを実装する。DBのcamelCase変換・revision数値化・通信・認証エラー分類は後続アダプタへ分離する。

未知フィールドを厳格拒否するため、DB列追加（to_jsonbの返却項目増加）やv2拡張時は検証契約とテストの更新が必要。自動補正・未知フィールドの黙示破棄はしない。巨大JSONの資源制限・信頼できないProxyの隔離は今回の保証外。
