# 隔離localStorage・Web Locks試験の契約

根拠はReview8 §3・5、LOCAL-MIGRATION.md、MIGRATION-UI.md、およびPR #14の限定承認。公開画面・実ユーザーデータ・Supabase/Auth・実DBへ接続しない。

## 実APIへ進む前のゲート

- 未接続アダプターと所有ガードの契約テストを先に通す。
- ランナー自身が新規生成・所有記録したプロファイルだけをPlaywright管理Chromiumへ渡す。任意パス・日常プロファイル・storageStateの指定を受け付けない。
- サーバーは127.0.0.1のOS割当ポートにbindし、同じ試験内の再起動では同一originを維持。既存4173や本番originを利用しない。固定HTML/JSだけを配信する。
- 所有検証後にランナーが許可情報を注入。専用入口はorigin・許可・secure context・top frameを確認してからAPIへ触れる。origin確認だけで所有を証明したとは扱わない。
- 実通信は固定資産だけ。Contextの外部要求は遮断・検出し、ブラウザには外部宛の到達不能ループバックproxy、背景通信抑止、非proxy UDP禁止を設定する。専用ページの通信API・WebRTCも禁止する。OS全体の通信監査の代替ではない。
- アプリのアダプターは旧／新キーgetItemと新キーsetItemだけ。旧キー投入はfixtureだけが旧キー不在・投入記録なしを確認し一度だけ実施する。再読込・再起動時に投入を繰り返さない。
- 既存メモリUIの禁止ガードは変更しない。実APIを許すのは専用入口だけ。他の永続APIと外部通信を禁止する。
- 終了後の削除は生成したprofileに限定。所有記録、正規パス、祖先と全子孫のシンボリックリンク／junction、ディレクトリ同一性を検査する。不成立なら削除せず失敗。親ディレクトリは再帰削除しない。

## 検証計画

1. 通常保存・再読込・管理Chromium終了後の同一profile再起動。
2. 合成旧データの取消・移行、pending／complete書込後の注入中断と再起動診断・明示復旧。実電源断の代替ではない。
3. 同一Context複数タブの同一revision競合、同時移行、ロック待ちと保持タブ終了後の解放。自動同期は追加せず明示再読込。
4. Storage取得・読取・書込・読戻しの障害注入とWeb Locks非対応。注入障害と実ブラウザ障害を区別する。
5. 診断→初回通常loadの状態変化。pending・不正は通常利用させない。
6. 最後に独立profileで容量試験。合成fillerは最大32回、合計16 Mi文字以下。上限内でQuotaExceededErrorがなければ未検証と報告する。値の消去や自動再試行はせずprofile全体の所有検証後に破棄。

既存型チェック・全Vitest・メモリE2E・ビルドも回帰確認する。生profile・生成物・ログはGit管理／配信しない。合成データだけをログにも原則出さず、件数・固定結果だけ報告する。

## 実行手順と確認結果

tools/memoで`npm.cmd run typecheck`、`npm.cmd test`を先に実行する。続いて`npm.cmd run build:preview`、`npm.cmd run test:e2e`、`npm.cmd run test:persistence`。永続化コマンドは専用ビルドとランナーを実行し、手動利用のサーバーや既存プロファイルを受け付けない。専用HTMLは合成データが実localStorageへ残ることを明示し、メモリ専用HTMLの注意書きを流用しない。

2026-10-29の管理Chromium試験で、13ケースを検証。通常保存／pending中断／complete中断の3ケースで、それぞれ実際のブラウザ終了後に同じprofileを再起動した。複数タブはrevision競合・同時移行・保持タブ終了後のロック解放を検証。容量試験は31回・投入試行合計6,289,792文字で実QuotaExceededErrorを再現し、アプリの追加保存をunknownとして停止、旧値と既存v2が不変であることを確認した。

API取得SecurityError、読取・書込・読戻し例外、pending／complete後の中断、Web Locks非対応は試験用注入であり、ブラウザ設定によるアクセス拒否・実クラッシュ・非対応ブラウザでの実証ではない。profile破棄は各ケースのChromium終了と所有検証が成功した場合だけ行う。ケース失敗・所有検証不能ならprofileを残し、成功扱いしない。容量上限内で例外を再現できない場合はUNVERIFIEDとし、検証成功件数へ加算しない。

実機・他ブラウザ・OS強制終了／電源断・OS再起動・ディスク障害・旧JSとの並行使用・悪意ある同一OSプロセスによる検査直後のパス差替えは保証しない。削除時の検査は同一ユーザーによる敵対的な同時変更を原子的に封じる仕組みではない。異常時は対象を保持する。試験成功を本番接続・公開切替・安全ゲート解除の承認と解釈しない。
