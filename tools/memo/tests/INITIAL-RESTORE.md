# 初期復元の契約とテスト方針

Step 5承認に従う。対象は合成メモリのみ。新旧キーのgetItemが正常終了し両方厳密にnullの時だけ、専用backupVersion=1から全件一括復元する。存在する値は空v3・旧[]・空文字列でも拒否する。

## 検証・書込

parseBackupBytesを再利用し、入力10 MiB・深度32・厳格UTF-8・BOM/重複JSONキー拒否。メモ10000、タグ5000、関連100000、履歴100000、候補16 MiB以下。元データ全体を既存v3検証器へ渡す。diagnoseBackupの行除外・関連統合は使用しない。ID・全属性・配列順序・履歴を保持し、version=3、migration=not-requiredのみ追加する。

同じストアの共有requestId予約と専用の不在時書込ポートを使う。通常transactのガードは緩めない。準備時に不変候補と保存領域を固定し、ファイル変更・取消・画面離脱・再準備で確認を失効。確認は一回消費。適用受付時、他検証・await前にrequestId予約。共通ロック内で両キー不在、候補妥当性、書込直前の両キー不在を確認し、一回だけ新キーへJSONを書き込む。旧キー不在と読戻し完全一致・全体妥当性を確認する。元データや既存キーの削除なし。

## 結果と画面

未書込拒否・確定成功・結果不明を区別。試行後の例外・quota・読戻し異常はunknown、自動診断/再書込/削除/ロールバックなし。手動診断は現在状態だけを返し、正常v3や両キー不在を過去成功/未保存の証明にしない。再操作は手動診断で両キー不在を確認後、新しい準備・確認・requestIdで行う。過去のunknown情報は後続拒否・取消・ファイル変更・通常画面へ移動してもメモリ内で保持する。ページ再読込・終了後の追跡保証なし。

件数・参考作成日時・平文/真正性保証なし・バックアップ後の変更/履歴喪失の限界を表示する。専用確認必須、部分選択なし。通常新規利用も可能だが初回保存後は初期復元不可。通常のドラフト・確認・書込中は開始不可。成功と通常画面読込は独立状態とする。

## 必須試験

- 正常全件と全属性/順序/原本不変、不正メモ/タグ/関連/履歴/重複/未知項目/版の全体拒否、解析とサイズ・件数境界。
- 両キー不在、空v3/履歴のみ/v2/pending/旧[]/旧空文字/破損/読取例外の区別、準備後/書込直前のキー出現、別ストア競合。
- 取消/差替え/離脱/古い世代/二重確認、requestId共有予約、quota/書込後例外/読戻し不一致、unknownの明示診断・再準備条件、過去unknown保持。
- 合成E2E：初回起動、通常利用、件数と説明、確認/取消/連打、不正全体停止、unknown/明示診断、成功と後続読込失敗、復元後の通常/ゴミ箱/タグ/履歴。

型チェック・全Vitest・全メモリE2E・4ビルド・差分検査を実行する。実保存先・実Web Locks・複数タブ実測・実機・大容量性能は未検証として引き継ぐ。非協調コード・ABA・バックアップ後に失われた履歴を防止/再生する保証はない。
