# C04 クラウド制御層契約

## 対象

C01のRPCアダプターとC03の認証境界を組み合わせ、8 RPCをUI非依存で制御する。実HTTP、製品UI、保存先切替は対象外である。

## 共通の認証境界

- 操作開始、資格情報取得後、RPC送信直前、応答反映前に同じ`AuthContext`が現在有効か確認する。
- 資格情報はC03内部で取得し、用途限定・1回限りのtransportへ閉じ込める。Bearer値をUI、公開状態、ログ、例外へ返さない。
- 資格情報の所有者と`AuthContext.userId`が異なる場合は送信しない。
- 送信前に認証が失効した場合はRPC呼出し0件で`stopped`を返す。
- 送信後に認証世代が変化した場合、応答を現在の画面状態へ反映せず`stale-response`を返す。
- 表示用の認証状態通知は書込許可ではない。操作ごとに`isCurrent()`と用途限定transportで検証する。
- controller内では同時に1操作だけを実行し、処理中の二重操作は`busy`で拒否する。

## load / save / resolve

- `load`は現在の所有者についてだけ実行し、古い応答を反映しない。
- `save`は操作開始時にID、本文、タグID、revision、requestId、所有者を固定する。
- C01が保存結果不明を返した場合は`unresolved`として固定要求を保持し、自動再送・自動ロールバック・自動resolveを行わない。
- `resolve`はこのcontrollerが発行した未確定保存要求だけを受け付ける。同じ所有者の新しい認証世代で明示的に照合できるが、別所有者への付け替えは拒否する。
- `no-record`は未実行の証明ではないため、保存要求をpendingのまま維持する。保存済みまたは削除済みreceiptを確認した場合だけ閉じる。

## 状態変更・削除・タグ操作

- `changeState`、`deletePermanently`、`emptyTrash`、`saveTag`、`deleteTag`も共通の認証・排他境界を通す。
- ID、action、revision、requestId、タグ名、一括削除対象とその順序を操作開始時にコピーして凍結する。
- 送信前の拒否は`stopped`またはC01の確定結果として返し、送信後の通信断・不正応答は`unresolved`として凍結済み操作を保持する。
- 状態変更の削除済みreceiptは過去要求の確定応答であり、現在のメモ状態が同じことを保証しない。
- 完全削除、一括削除、タグ保存、タグ削除には、正式SQL上の照合RPCがない。状態変更にも保存用`memo_resolve_request`を流用しない。架空のresolve機能を追加しない。
- `acknowledgeUncertain()`は、利用者側が再読込・手動確認等を行った後にcontrollerのメモリ内追跡を終了するための操作である。成功・失敗を確定せず、RPC呼出しや再送も行わない。controllerが発行していない操作や二重確認は拒否する。
- 明示確認前の未確定操作は`dispose()`を`pending`で止め、画面終了だけで結果不明を消失させない。

## dispose

- 通信中は`busy`、未確定の保存またはその他操作が残る場合は`pending`を返す。
- 保存要求は明示resolveによる確定後、その他操作は結果を断定しない明示確認後にのみ追跡を閉じられる。
- `applied`後は新規操作を`disposed`で拒否する。

## C01・C02との境界

- C01の`CloudResult`、厳格なDB応答検証、所有者結合、エラー分類を変更しない。
- C02の固定開発origin、8 RPC、リダイレクト拒否、回数制限、`unverified`等のテスト専用契約を緩めない。
- 現在の`createMemoSdkAuth()`には製品用RPC senderを接続していない。後続PRでは、検証済みorigin・RPC・リダイレクト拒否・応答出所の条件を満たすsenderを製品composition rootだけで注入する。
- Auth用`safeFetch`の許可範囲は拡張しない。

## 通信なし試験で保証すること

- 送信前失効・資格情報取得中の世代変更・所有者不一致ではRPC呼出し0件となる。
- 送信内容と結果不明時の操作スナップショットが後続入力変更で変化しない。
- 送信後失効と古い応答を反映せず、自動再送しない。
- 結果不明操作に存在しない照合機能を割り当てず、明示確認と追跡終了を結果判定から分離する。
- 通信中のdispose、二重操作、偽造・二重確認を拒否する。
- Bearer値と通信例外本文が公開結果へ混入しない。

## 未検証事項

- 実Supabase、実Bearer通信、RLS、GRANT、PostgRESTの実動作。
- 製品UIへの反映、ドラフト保護、保存先切替。
- 結果不明後に利用者へ提示する再読込・手動確認UI。
- 自動同期、自動転送、自動フォールバック、自動再送は実装しない。
