# メモツール Ver1.1.0 入力契約のテスト方針

第二弾の旧データ・v2・DB snapshot読み取り検証は、別紙[承認済み契約とテスト方針](READ-VALIDATION.md)を参照。第一弾の入力検証165件は引き続き維持する。

第三弾のWeb Locks排他・非破壊移行・pending復旧は、[ローカル移行のテスト方針](LOCAL-MIGRATION.md)を参照。実保存データや既存画面には接続しない。

ローカルメモの読込・作成・更新とrequestIdのA案は、[ローカル保存の契約・テスト方針](LOCAL-SAVE.md)を参照。永続的な要求履歴や再送の冪等性は保証しない。

タグ管理・ピン・ゴミ箱・使用件数の追加契約は、[ローカル追加操作のテスト方針](LOCAL-OPERATIONS.md)を参照。

一覧の検索・タグOR絞込・並び替え・詳細前後移動は、[メモ一覧の読み取り契約](MEMO-QUERY.md)を参照。保存・画面接続は行わない。

編集ドラフト・保存試行・離脱確認・一覧復帰の純粋ロジックは、[編集と遷移の状態契約](EDITOR-STATE.md)を参照。実保存先・画面・認証への接続は行わない。

既存のローカル操作・一覧・編集状態を接続する制御層は、[ローカル制御層の結合テスト方針](LOCAL-CONTROLLER.md)を参照。合成保存先だけで検証する。

独立したメモリ保存UI・ビルド・隔離Chromium E2Eは、[ブラウザUIの試験方針](BROWSER-UI.md)を参照。公開画面・実保存領域には接続しない。

合成データの事前診断・明示移行・pending復旧UIは、[移行・復旧UIの契約](MIGRATION-UI.md)を参照。起動では診断だけを行う。

対象は新規入力用の純粋関数と最小限のドメイン型。VitestはNode環境で実行し、DOM・localStorage・ネットワーク・認証・実DBは使用しない。

## 根拠と期待値

正式根拠は [統合仕様§2・6](../doc/v1.1.0/memo_v1_1_implementation_review8.md)、[SQL](../doc/v1.1.0/memo_v1_1_schema_review8.sql) の `memo_edge_spaces`（13〜17行）、`memo_trim_edges`（19〜21行）、`memo_valid_text`（23〜41行）、`memo_tag_key`（42〜46行）。テスト値は仕様から独立に列挙し、実装の正規表現・定数を期待値生成に使わない。

| 観点 | 期待結果 | 根拠 |
|---|---|---|
| 明示空白25コードポイント | タイトル・タグの両端のみ除去。内部の通常空白は保持 | §2、memo_edge_spaces / memo_trim_edges |
| 本文保持 | 前後空白、LF・TAB、Unicode表現を変換しない | §2、memo_valid_text |
| タイトル100/101、本文10000/10001、タグ30/31 | 整形後の上限ちょうどは許可、1超過は拒否。ASCII・日本語・絵文字・結合文字で検証 | §2・6、SQL char_length |
| Unicodeの単位 | 絵文字のサロゲートペアは1コードポイント、e＋結合文字は2。NFC/NFD変換なし | §2・6 |
| C0/C1制御文字 | 全対象を列挙。本文のみLF/TAB許可、CR/CRLFは拒否し変換しない | §2、memo_valid_text |
| U+2028/U+2029 | タイトル・タグの内部は拒否、両端は除去。本文は保持 | §2、memo_valid_text |
| 孤立サロゲート・NUL | クライアントで拒否。DB型入力エラーを模擬したとは扱わない | §2・6 |
| 空タイトル | 本文に実質内容があれば「無題」、両方実質空なら拒否。明示した非空タイトルは空本文を許可 | §2。これはSQLの自動補完ではない |
| 空タグ | 整形後空文字は拒否 | §2、memo_valid_text |
| ASCIIキー | A〜Zのみa〜zへ。非ASCII・結合表現・前後空白はtagKey自体で変換しない | §2、SQL translate |
| 不正な実行時型 | null等を文字列へ暗黙変換せず拒否。エラーに入力値を含めない | 関数のstring契約・機密保護ルール |
| 型の対応 | 必要最小限の7型を正式型定義とコンパイル時に照合 | types.contract.ts、review8型定義 |

`normalizeTagName`で検証・整形した表示名に`tagKey`を適用する。`tagKey`単体はSQLと同じ変換関数であり、タグ名検証の代用ではない。関数間のエラー優先順位やメッセージ文字列はDBエラー契約と同一とは規定しない。

## 実行・完了条件

メモ配下で `npm ci`、`npm run typecheck`、`npm test`。PowerShellでnpm.ps1が制限される場合は `npm.cmd` を使い、実行ポリシーを変更しない。

型チェックと全テストが正常終了し、現行HTML/CSS/JS・正式資料・実設定・既存保存データに変更がないことを確認する。失敗時は実装・テスト・仕様を切り分け、解釈が必要なら停止して確認する。期待値を変える場合は仕様根拠と理由を報告する。

SQL関数を読み取った静的対応確認であり、SQLの実行結果とTypeScriptの一致を実証するものではない。DB試験の既存33項目PASSとも別の検証。ブラウザ・画面・移行・保存・RLS等はこのPRの保証範囲外。
