# メモツール Ver1.1.0｜review7 統合実装仕様（未検証）

> **設計草案。SQL未実行、実DB・ブラウザ未検証。本番適用禁止。** review4以前の追記型文書を置き換える単一の現行契約。過去のreviewファイルは経緯確認用であり実装根拠にしない。

## 1. 基本方針

- URL `tools/memo/memo.html` を維持。Vanilla TypeScript、GitHub Pages、共通ヘッダー・フッター。Vitest／Playwrightを予定。既存画面の確定仕様は `memo_v1_1_layout_review2.drawio` に従う。
- ローカルとSupabaseは完全独立。同期・転送・障害時の自動フォールバックなし。ログアウトでローカルへ戻る。保存は明示操作のみ。保存後は詳細に留まる。
- 未保存・結果不明・競合時のドラフトは**そのタブのメモリ内**に保持。ページ更新・ブラウザ終了後の復元は保証しない。画面離脱・保存先変更・ログアウトは未保存確認。通信断でもクラウド下書きをlocalStorageへ書かない。
- ゴミ箱は論理削除。タグ関連はゴミ箱内でも維持。**タグ使用件数はゴミ箱外のメモのみ**（移動で減、復元で増）。タグマスターは未使用でも保持。

## 2. 共通入力規則（確定方針、実装・DB照合未完了）

- 文字数はUnicode**コードポイント**数。タイトル100、本文10000、タグ名30を上限。孤立サロゲート、U+0000、禁止制御文字は拒否。Unicode正規化（NFC等）は**行わない**。
- 前後空白を除去する対象は**タイトルとタグ名のみ**。空白集合は ECMAScript `trim()` 相当の明示集合：U+0009〜000D, U+0020, U+00A0, U+1680, U+2000〜200A, U+2028, U+2029, U+202F, U+205F, U+3000, U+FEFF。内部空白は保持するが、タイトル・タグ名の改行・タブは禁止。内部U+2028・U+2029も改行区切りとみなして禁止。
- 本文は前後空白を含め入力値を保持。改行LF（U+000A）とタブ（U+0009）は許可、CR（U+000D）は禁止し**自動変換しない**。それ以外のC0/C1制御文字（U+0000〜001F, U+007F〜009F）は拒否。タイトル・タグ名はC0/C1をすべて禁止。
- 新規入力はまずタイトル・タグ名の前後空白を除去し、その後に制御文字・内部改行・文字数を検証する（除去前の先頭・末尾TAB/LF等は許容）。本文は整形しない。本文が空白だけかの判定にも上記空白集合を使う。タイトルが空白だけで本文に実質内容があれば `無題` を採用。両方実質空ならUI／TSで保存禁止。明示的に「無題」と入力した場合は本文が空でも保存できる。DBは補完前の入力を識別できないため、正規化済みの非空タイトルと本文の各値だけを検証し、「無題」だけを特別に拒否しない。保存前の正規化済み値に文字数制限を適用。
- タグ一意性は**ASCIIの A〜Z のみ a〜z に折りたたんだキー**で比較。非ASCIIは変換しない（`İ` と `i`、`Ä` と `ä` は異なる）。表示用の元の文字列は維持。ローカル／SQLの両方で同じキー生成関数を実装し、DBの `lower()` を使わない。タグはユーザーごとにキー一意。
- SQL側は明示空白集合による検証、文字数（`char_length`）、制御文字拒否、タグキー制約を実装すること。**review7 SQLに検証関数を追加したが、実DBでの動作およびTSとの一致は未検証。クラウド保存は接続しないこと。** JS `trim()`／SQL `btrim()`／SQL `lower()` の直接混用は禁止。

## 3. 旧データ移行（安全性優先）

- 旧キー `myhomepage.memo.items.v1` は絶対に変更しない。新キー `myhomepage.memo.data.v2` は単一JSON。新キーなし・旧キーなしなら `migration.status='not-required'`。
- 旧キーがあればユーザーの明示承認後にのみ移行。キャンセル時は無変更。Web Locks排他下で旧キーの生文字列を記録、全件検証後UUID再発行、`pending` 書込→読戻し照合→`complete` 書込→再照合。失敗・破損・旧キー変化時は停止して復旧案内。自動修復・上書き禁止。
- 旧形式は配列、各要素 `id/title/text/createdAt/updatedAt` がstring、ID非空・重複なし、日時は厳格ISO 8601インスタント、未知項目・欠落・不正文字・文字数超過・タイトルの前後空白・空タイトル等は**全体中断**。移行時にtrim／正規化／切詰め／「無題」補完をしない。新キーが既にあれば無断上書きしない。
- ローカルのすべての書込は同じ `navigator.locks` 排他で新キー再読込・検証・revision照合・単一JSON書込・読戻し。Web Locks非対応なら書込・移行を無効化。旧版JSを開いたままの並行操作はサポート外。
- **ロック取得後**に新キーの有無・妥当性と旧キーの生文字列を再確認する。別タブが既に移行した場合、上書きせず現在の新キーを検証して終了する。ロック取得前の判定だけで書き込まない。
- 起動時に `pending` があれば通常画面へ進めない。旧キーの生文字列一致、移行後全件の内容・順序・UUID一意性・revision・初期状態・書込済みスナップショットを検証し、同じロック下で `complete` へ進め、読戻し検証する。不一致は**停止**して非破壊の復旧案内を表示。`complete` も構造・整合性を検証してから使用する。
- 移行時は元配列の順序、タイトル・本文（`text`）・作成日時・更新日時を**文字列のまま保持**し、各メモに新UUIDを付与。`pinnedAt=null`、`deletedAt=null`、`revision=1`、`lastRequestId=null`、タグと関連は空。旧IDは再利用しない。新旧の項目別照合を行い、タイトル・本文・日時の一文字も書き換えない。本文の前後空白は許可・保持する。新規入力の「無題」補完は移行には適用しない。
- 移行前の旧値検証は**新規入力の整形処理とは分離**する。旧タイトルの前後空白・不正文字・空値、旧本文の禁止制御文字・文字数超過、日時不正などは全件中断。本文の前後空白だけでは中断しない。

## 4. クラウドRPC契約（review7 SQL草案）

- `memo_save` は `p_id, p_title, p_body, p_tag_ids, p_expected_revision, p_request_id`。同一ユーザーの同一requestIdは、操作・ID・期待revision・タイトル・本文・ソート済みタグID集合に結びつく。初回作成のみ使用済みID登録。更新はrevision一致かつゴミ箱外のみ。メモ・関連・要求台帳を同一トランザクションで書込。
- ハッシュ対象はPostgreSQL `jsonb` を含むサーバー構築文字列を**`convert_to(...,'UTF8')`** で符号化し `digest(...,'sha256')`。クライアントはハッシュを自前再現しない。
- `memo_resolve_request` は**凍結した全送信内容**を受け、サーバーが保存時と同じハッシュを再計算して照合する。結果が無ければ `null`（未実行の証明ではない）。一致すれば `{status:'saved',result:{memo,tagIds}}`、完全削除済みなら `{status:'previously-applied-deleted'}`。異なる内容のrequestId再利用は拒否。照合RPCは読み取り専用で現在のタグ存在確認をしない。
- `memo_save` の生戻り値は `{memo:DbMemoRow,tagIds:UUID[]}` **または** `{status:'previously-applied-deleted'}`。アダプタで `SaveOutcome` に変換し、削除済みreceiptを現存メモとして扱わない。DB行snake_caseとドメインcamelCaseを直接混同しない。履歴上の成功は現在の存在・内容の証明ではない。
- 完全削除ではメモ・関連を削除し、対象メモに属する**すべての台帳resultをnull化**。使用済みID、要求ID、操作種別、照合ハッシュ、削除済み印だけ保持。タイトル・本文・タグ内容を台帳に残さない。バックアップ・ログまで即時消去する保証はない。ハッシュは暗号化ではない。
- `memo_load_snapshot` は一つのSQL文でメモ・タグ・関連を返す。未認証時の `null` は権限エラー（空データ扱い禁止）。取得後はUUID、日時、revision、参照整合性を実行時検証する。
- ピン／ゴミ箱移動／復元／タグ削除はrevision競合を検出。タグ削除時は関連メモ（ゴミ箱内含む）のrevisionを同一トランザクションで増やす。タグ名変更だけではメモrevisionを増やさない。
- ゴミ箱一括削除は確認時の**全ID＋revision**と現状が完全一致したときのみ原子的に削除。`requestId` はこの操作ではクライアント内識別用でSQL台帳には保存しない。応答不明時は元対象のみ再確認し、追加されたゴミ箱メモを巻き込まない。**認証と通信が正常に成立した取得**で、元対象全件が不在と確認できたときだけ削除済みと判定する。一部でも残る／取得失敗なら成功扱いせず、元対象以外に削除対象を拡大しない。再実行には再確認・再承認を要する。個別完全削除も同じ原則。
- 保存要求を送信する際、`SubmittedSave` を**不変スナップショット**として保持し、送信後の編集は別の最新ドラフトに保存する。応答不明時は自動再送しない。まず凍結要求で `memo_resolve_request` を照合し、履歴上の成功と現在の状態を区別する。`null` は未実行の証明ではない。再試行は**同一内容・同一requestId**のみ。変更内容の保存は結果確認後に新requestIdで実施。
- 保存中は保存先切替・ログアウト・画面遷移を待機／抑止する。非同期応答を画面へ反映する前に、**保存開始時の保存先・認証ユーザーID・画面セッション識別子**が現在と一致するか検証し、不一致なら古い応答を現在の画面へ反映しない。ログアウトは明示操作でローカルへ戻すが、クラウド要求をローカルへ転送・保存しない。ドラフトがある場合は離脱確認を行う。
- 競合時は編集内容をタブ内メモリに保持したまま、最新状態の非破壊再取得を案内する。削除済みreceiptは過去の処理履歴であり現存メモではない。通信失敗時に保存済み表示やドラフト破棄をしない。

## 5. UI／テスト／ゲート

- 一覧：ピン留めメモは通常メモより先に表示し、ピン同士は `pinnedAt` 降順（新しくピン留めしたものが先頭）。同時刻はIDで安定ソート。リアルタイム検索（タイトル・本文・タグ名）、タグ複数OR＋文字検索AND、並び替え、ピン優先、一覧へ戻る際の絞込／スクロール保持。カードのピンアイコンは表示のみ、操作は `︙`。詳細には独立した複製ボタン。複製は未保存の新規編集でピンは引き継がない。
- ゴミ箱は読取専用、復元・完全削除・空にする操作に確認。音声認識は日本語、本文追記・新規メモ作成（タイトル `音声メモ-YYYYMMDD-HHmm`）、手動保存。音声認識非対応・権限拒否・認識失敗時は手入力を継続でき、入力済み内容は保持。認識結果が文字数上限を超える場合は超過文字列を本文へ反映せず、警告して手入力へ戻す。PC／スマホの共通フッターを維持。
- テスト：Unicode空白／制御文字／絵文字／コードポイント境界、タグASCIIキーのTSとDB一致、旧データ全件中断、Web Locks／pending復旧、ハッシュ再送・完全削除・タグ削除後再送、SQL権限、RLS、同時更新、スナップショット、スマホ画面。
- **ゲート：全面実装不可。** まずSQL入力制約・タグ一意キーとTSバリデータの一致を検証し、テスト用DBでSQL実行・権限・競合を検証。限定的にTS骨格、旧データの読み取り検証、Web Locks、確定済みUI骨格は先行可能。本番DBへの適用と既存localStorageの変更は禁止。


## 6. review7検証前の注意事項

- SQLの `memo_valid_text`／`memo_trim_edges`／`memo_tag_key` は**未実行の設計案**。`ascii()` のUTF-8コードポイント判定、`translate` の非ASCII保持、照合順序、`char_length`、空白集合をテストDBで確認する。
- クライアントは `Array.from(s).length` 等でコードポイント数を検証し、孤立サロゲートを明示的に拒否する。SQLとTSの共通テストベクトルを用意し、**一致しなければクラウド保存に進まない**。NULはPostgreSQL textで保持できないため、DB型入力エラーも拒否として確認する。
- 「空白タイトル＋本文あり→無題」は新規入力のUI／TS整形で行う。DB RPCは正規化後の非空タイトルを受け取り、独自の暗黙補正をしない。本文のみ空白でタイトルが実質非空ならタイトル付きメモとして保存できる。
- 完全削除後も台帳のハッシュ・要求ID等は残る。バックアップ、監査ログ等を含めた即時・完全消去は保証しない。
- `memo_change_state` の削除済み履歴照合など、全RPCの結果型と権限は実DBで検証が必要。SQLはテスト環境専用で、本番には適用しない。

- テスト用DBの `server_encoding` が `UTF8` であることを適用前に確認する。別エンコーディングでの一致は保証しない。
- `memo_change_state` の過去要求が完全削除後に再送された場合、SQLSTATE `P0002` は「現存メモの保存成功」へ変換しない。アダプタは削除済み履歴として別途扱い、現在の画面・ドラフトを勝手に確定・破棄しない。
