# メモツール Ver1.1.0｜review5 統合実装仕様（未検証）

> **設計草案。SQL未実行、実DB・ブラウザ未検証。本番適用禁止。** review4以前の追記型文書を置き換える単一の現行契約。過去のreviewファイルは経緯確認用であり実装根拠にしない。

## 1. 基本方針

- URL `tools/memo/memo.html` を維持。Vanilla TypeScript、GitHub Pages、共通ヘッダー・フッター。Vitest／Playwrightを予定。既存画面の確定仕様は `memo_v1_1_layout_review2.drawio` に従う。
- ローカルとSupabaseは完全独立。同期・転送・障害時の自動フォールバックなし。ログアウトでローカルへ戻る。保存は明示操作のみ。保存後は詳細に留まる。
- 未保存・結果不明・競合時のドラフトは**そのタブのメモリ内**に保持。ページ更新・ブラウザ終了後の復元は保証しない。画面離脱・保存先変更・ログアウトは未保存確認。通信断でもクラウド下書きをlocalStorageへ書かない。
- ゴミ箱は論理削除。タグ関連はゴミ箱内でも維持。**タグ使用件数はゴミ箱外のメモのみ**（移動で減、復元で増）。タグマスターは未使用でも保持。

## 2. 共通入力規則（確定方針、実装・DB照合未完了）

- 文字数はUnicode**コードポイント**数。タイトル100、本文10000、タグ名30を上限。孤立サロゲート、U+0000、禁止制御文字は拒否。Unicode正規化（NFC等）は**行わない**。
- 前後空白を除去する対象は**タイトルとタグ名のみ**。空白集合は ECMAScript `trim()` 相当の明示集合：U+0009〜000D, U+0020, U+00A0, U+1680, U+2000〜200A, U+2028, U+2029, U+202F, U+205F, U+3000, U+FEFF。内部空白は保持するが、タイトル・タグ名の改行・タブは禁止。
- 本文は前後空白を含め入力値を保持。改行LF（U+000A）とタブ（U+0009）は許可、CR（U+000D）は禁止し**自動変換しない**。それ以外のC0/C1制御文字（U+0000〜001F, U+007F〜009F）は拒否。タイトル・タグ名はC0/C1をすべて禁止。
- 本文が空白だけかの判定にも上記空白集合を使う。タイトルが空白だけで本文に実質内容があれば `無題` を採用。両方実質空なら保存禁止。保存前の正規化済み値に文字数制限を適用。
- タグ一意性は**ASCIIの A〜Z のみ a〜z に折りたたんだキー**で比較。非ASCIIは変換しない（`İ` と `i`、`Ä` と `ä` は異なる）。表示用の元の文字列は維持。ローカル／SQLの両方で同じキー生成関数を実装し、DBの `lower()` を使わない。タグはユーザーごとにキー一意。
- SQL側は明示空白集合による検証、文字数（`char_length`）、制御文字拒否、タグキー制約を実装すること。**review5 SQLにはまだ反映しきれていないため、クラウド保存を実装しないこと。** JS `trim()`／SQL `btrim()`／SQL `lower()` の直接混用は禁止。

## 3. 旧データ移行（安全性優先）

- 旧キー `myhomepage.memo.items.v1` は絶対に変更しない。新キー `myhomepage.memo.data.v2` は単一JSON。新キーなし・旧キーなしなら `migration.status='not-required'`。
- 旧キーがあればユーザーの明示承認後にのみ移行。キャンセル時は無変更。Web Locks排他下で旧キーの生文字列を記録、全件検証後UUID再発行、`pending` 書込→読戻し照合→`complete` 書込→再照合。失敗・破損・旧キー変化時は停止して復旧案内。自動修復・上書き禁止。
- 旧形式は配列、各要素 `id/title/text/createdAt/updatedAt` がstring、ID非空・重複なし、日時は厳格ISO 8601インスタント、未知項目・欠落・不正文字・文字数超過・旧値の前後空白・空タイトル等は**全体中断**。移行時にtrim／正規化／切詰め／「無題」補完をしない。新キーが既にあれば無断上書きしない。
- ローカルのすべての書込は同じ `navigator.locks` 排他で新キー再読込・検証・revision照合・単一JSON書込・読戻し。Web Locks非対応なら書込・移行を無効化。旧版JSを開いたままの並行操作はサポート外。

## 4. クラウドRPC契約（review5 SQL草案）

- `memo_save` は `p_id, p_title, p_body, p_tag_ids, p_expected_revision, p_request_id`。同一ユーザーの同一requestIdは、操作・ID・期待revision・タイトル・本文・ソート済みタグID集合に結びつく。初回作成のみ使用済みID登録。更新はrevision一致かつゴミ箱外のみ。メモ・関連・要求台帳を同一トランザクションで書込。
- ハッシュ対象はPostgreSQL `jsonb` を含むサーバー構築文字列を**`convert_to(...,'UTF8')`** で符号化し `digest(...,'sha256')`。クライアントはハッシュを自前再現しない。
- `memo_resolve_request` は**凍結した全送信内容**を受け、サーバーが保存時と同じハッシュを再計算して照合する。結果が無ければ `null`（未実行の証明ではない）。一致すれば `{status:'saved',result:{memo,tagIds}}`、完全削除済みなら `{status:'previously-applied-deleted'}`。異なる内容のrequestId再利用は拒否。照合RPCは読み取り専用で現在のタグ存在確認をしない。
- `memo_save` の生戻り値は `{memo:DbMemoRow,tagIds:UUID[]}` **または** `{status:'previously-applied-deleted'}`。アダプタで `SaveOutcome` に変換し、削除済みreceiptを現存メモとして扱わない。DB行snake_caseとドメインcamelCaseを直接混同しない。履歴上の成功は現在の存在・内容の証明ではない。
- 完全削除ではメモ・関連を削除し、対象メモに属する**すべての台帳resultをnull化**。使用済みID、要求ID、操作種別、照合ハッシュ、削除済み印だけ保持。タイトル・本文・タグ内容を台帳に残さない。バックアップ・ログまで即時消去する保証はない。ハッシュは暗号化ではない。
- `memo_load_snapshot` は一つのSQL文でメモ・タグ・関連を返す。未認証時の `null` は権限エラー（空データ扱い禁止）。取得後はUUID、日時、revision、参照整合性を実行時検証する。
- ピン／ゴミ箱移動／復元／タグ削除はrevision競合を検出。タグ削除時は関連メモ（ゴミ箱内含む）のrevisionを同一トランザクションで増やす。タグ名変更だけではメモrevisionを増やさない。
- ゴミ箱一括削除は確認時の**全ID＋revision**と現状が完全一致したときのみ原子的に削除。`requestId` はこの操作ではクライアント内識別用でSQL台帳には保存しない。応答不明時は元対象のみ再確認し、追加されたゴミ箱メモを巻き込まない。
